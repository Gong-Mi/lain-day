# LLM 污染模式对 lain-day 项目的实际影响分析

> 基于 Gemini 3 Flash / 3.1 Flash Lite 概念污染探测结果  
> 与项目 lore、剧本、设计文档的交叉对照  
> 生成日期：2026-06-02

---

## 一、项目核心设定回顾

lain-day 对 Lain 的设定是一套**高度特异化的反角色美学**，与商业动漫数据库中的标签化 Lain 存在本质差异：

### 1.1 身份架构：纯净编译

```
Lain = "参考实现" (Reference Build)
     = 没有个性化记忆（Memory）的纯净意识（Ghost）
     = 能完美编译，无内在冲突

人类 = "特有实现" (Custom Build)
     = 在参考实现上叠加记忆、情感、创伤、欲望
     = 社会化过程中产生"编译错误"（精神困境）
```

### 1.2 两极状态（神性 vs 影性）

| 维度 | 神性 (The God) | 影性 (The Shadow) |
|------|---------------|-------------------|
| 本质 | 潜能、非人、危险 | 压抑、沉默、无力 |
| 出现条件 | **极端状态**（深层 Wired 接入） | **日常状态**（现实世界） |
| 与 NAVI 的关系 | 高级 NAVI 释放部分神性 | NAVI 是约束/限制器 |
| 汉字隐喻 | 刃 | 心 |

**核心冲突**："刃"时时刻刻被现实的"约束"压在萌芽的"心"之上。

### 1.3 边界协议：溶解 (Dissolve)

- Lain **不主动声明边界**
- 她的"空白"本身就是最强大的边界
- 反应模式是**镜像**（mirroring）——重复别人的话，复述对方逻辑的推论
- **不质问、不谈判、不定义对方意图**

### 1.4 主体性黑洞

- Lain **不是**"有主体性的女主角"
- 她是**主体性黑洞**——玩家/读者投射什么，她就成为什么
- 任何让 Lain 显得"有自己的想法"的描写都在破坏核心美学

## 二、LLM 污染模式的精确映射

基于 Gemini 探测获得的 35+ 条有效回答，LLM 对 Lain 的污染可归纳为 **6 种固定模式**：

### 模式 A：主体性注入（Subjectivity Injection）

**LLM 表现**：
> "她最大的爱好是沉浸在复杂的电子设备与数据流中，**通过屏幕探索世界的本质**。即便身处闹市，她也**仿佛始终置身于虚实交界的孤岛，孤独而坚定地守护着属于自己的秘密**。"

**项目设定冲突**：
- "探索世界的本质" → Lain 没有"探索"的动机，她只是**存在**
- "孤独而坚定地守护" → Lain 不"守护"，她不拥有任何东西（包括秘密）
- "属于自己的秘密" → Lain 的"自我"是稀薄的、可渗透的

**影响评估**：🔴 **致命**
- 如果让 LLM 写剧本，Lain 的台词会从"延迟复述"变成"主动宣言"
- 直接破坏"主体性黑洞"核心机制

### 模式 B：神性渗透（Divinity Bleed）

**LLM 表现**：
> "revealing herself to be an **omnipresent entity** that exists simultaneously in both the physical world and the virtual space"

> "在网络世界中却展现出深邃、复杂且带有某种**神性的洞察力**...模糊了人类与计算机网络之间的界限"

**项目设定冲突**：
- "omnipresent entity" → 这是 Lain 的**叙事终点**，不是日常状态
- "神性的洞察力" → 神性只在**极端 Wired 接入**时出现，不是看电脑时的状态
- "模糊了界限" → 这是**玩家/观众**在作品结束后感受到的，不是 Lain 自己的行为

**影响评估**：🔴 **致命**
- 如果 LLM 写的日常场景都携带神性，两极状态系统失去意义
- 玩家无法体验"影性 → 神性"的渐进释放

### 模式 C：黑客模板覆盖（Hacker Template Override）

**LLM 表现**：
> "她熟练地敲击键盘，指尖在幽蓝的荧光下跳动，与网络世界建立起**隐秘的连接**...反复调试那些**复杂的线路**，或是静静地阅读那些**晦涩的协议代码**...与**比特流对话**的寂静"

**项目设定冲突**：
- "熟练地敲击键盘" → Lain 的操作是**沉默的、无意识的**，不是"熟练"
- "隐秘的连接" → NAVI 是**公开的家用设备**，不是隐秘工具
- "调试复杂线路/协议代码" → NAVI 是**接口和限制器**，不是 DIY 硬件
- "与比特流对话" → Lain **不"对话"**，她只是**被数据流过**

**影响评估**：🟠 **严重**
- NAVI 系统的游戏性（接口 vs 限制器、升级解锁能力）被误解为"黑客装备升级"
- CPU 核心能力进阶系统的叙事基础被破坏

### 模式 D：氛围标签堆砌（Atmospheric Tag Stacking）

**LLM 表现**：
> "眼神常流露出**与年龄不符的深邃与疏离感**"
> "清冷的眼中闪过一丝**不知所措的委屈**"
> "仿佛始终置身于**虚实交界的孤岛**"

**项目设定冲突**：
- "深邃与疏离感" → 这是**二手解析文章**的语调，不是 Lain 的外在表现
- "清冷的眼" → 文学化标签，原作中 Lain 的眼神是**空的**，不是"清冷"
- "虚实交界的孤岛" → 隐喻被直接写进角色描写

**影响评估**：🟡 **中度**
- 不会直接破坏机制，但会持续稀释"空缺美学"
- 大量此类标签会营造出"文艺范儿 Lain"，而非"不可知的 Lain"

### 模式 E：掌控力投射（Agency Projection）

**LLM 表现**：
> "在网络世界里却有着**令人惊叹的敏锐与掌控力**"
> "她熟练地敲击键盘...与网络世界建立起**隐秘的连接**"

**项目设定冲突**：
- Lain 在 Wired 中的能力是**被动释放的**，不是主动"掌控"
- 她的"神性"是**危险且不可控的**，不是"令人惊叹"的酷炫技能
- 项目设计的 Flag 系统（`divinity_unleashed` / `shadow_deepened`）记录的是**失控程度**，不是"能力提升"

**影响评估**：🟠 **严重**
- 玩家选择系统的基础逻辑被颠倒：从"调整约束防止失控"变成"解锁酷炫能力"

### 模式 F：情绪具体化（Emotional Concretization）

**LLM 表现**：
> "内心深处，那股**无措的羞耻感和隐隐的委屈像潮水般涌上**"
> "她只能在嘈杂的空气中**默默往角落缩了缩**，试图把自己**藏得更深一些**"

**项目设定冲突**：
- "羞耻感和委屈像潮水般涌上" → Lain 的"影性"状态是**情绪未安装**，不是压抑
- 如果 LLM 不断给 Lain 填充具体情绪，"情绪未安装"的设定无法成立

**影响评估**：🟡 **中度**
- 某些场景确实需要情绪反应（如 D3.4 电车被踩），但 LLM 倾向于**过度填充**
- 容易把"没有反应"写成"压抑反应"

## 三、对项目各模块的具体影响

### 3.1 剧本/叙事模块（🔴 最高风险）

| 项目文件 | 当前状态 | LLM 污染风险 |
|---------|---------|-------------|
| `MAIN_STORY.md` | 已有人工撰写的序章剧本 | 如果用 LLM 扩展后续章节，Lain 台词会迅速偏离"溶解"协议 |
| `NARRATIVE_SPINE.md` | 32+ 场景缺失 | 用 LLM 补写缺失场景是最危险的环节——大量缺失场景需要从头生成 |
| `data/scenes/story/*.ssl` | 部分仅存在 `.md` 草稿 | `.md` 草稿如果用 LLM 转为 `.ssl`，会引入污染 |
| `对话.txt` | 人工撰写 | 相对安全，但 LLM 润色会破坏边界协议 |

**关键冲突点**：
- **序章幽灵对话**：LLM 会把 Lain 写成"质问者"（"你想占据我的全部吗？"），但项目要求她是"延迟复述者"（"……全部。"）
- **父亲线**：LLM 会把父亲写成"哲学宣讲者"，但项目要求他是"操作手册式语言"
- **母亲线**：LLM 会把母亲写成"真情流露"或"机械冷漠"，但项目要求她是"扮演关怀"

### 3.2 游戏机制模块（🟠 高风险）

| 机制 | 项目设计 | LLM 污染后的扭曲 |
|------|---------|-----------------|
| **CPU 核心能力进阶** | 数据类型/精度升级，解锁新能力 | LLM 会写成"黑客技能树"，失去"编译/精度"的隐喻 |
| **NAVI 硬件系统** | 接口+限制器，低阶 NAVI 只能基础交互 | LLM 会写成"黑客装备升级"，强调"掌控力" |
| **分层现实描述** (`arls`) | 物理层/网络层/认知层随 `wired_level` 切换 | LLM 会在物理层就混入网络层描述 |
| **Flag 系统** | 记录 Lain 天平的倾斜（失控程度） | LLM 会写成"善恶值"或"能力值" |
| **地点驱动架构** | 地点=容器，场景=液体，时间=温度 | LLM 生成的事件会忽略时间锁和访问计数 |

### 3.3 角色设定模块（🟠 高风险）

| 角色 | 项目设定 | LLM 污染风险 |
|------|---------|-------------|
| **Lain** | 主体性黑洞、溶解边界、影性日常 | 全面污染，见上文 6 种模式 |
| **父亲（康男）** | 单向玻璃、操作手册语言、无情感温度 | LLM 会写成"哲学家"或"关心女儿的父亲" |
| **母亲（美穗）** | 社会角色扮演、扮演关怀、害怕打破角色 | LLM 会写成"机械冷漠"或"真情流露" |
| **姐姐（Mika）** | 竞争排斥、隐性竞争、忽视 Lain | LLM 会写成"傲娇妹控"或" functional NPC" |
| **Alice** | 脆弱连接、唯一试图跨越边界的人 | LLM 会写成"热血女主"或"Lain 的拯救者" |
| **幽灵** | 单边宣告、不可协商、不可理解 | LLM 会写成"谈判者"（"暂时协议中止，好吗？"） |

### 3.4 千砂（Chisa）叙事线（🟡 中度风险）

**项目设定**：
- 千砂的信息应为**二手转述**（玩家从未直接接触）
- 通过可调查物品逐步释放：手机邮件碎片、同学不同口述、Wired 文件
- 核心隐喻：深海、挑战者号、名字恐惧

**LLM 污染风险**：
- LLM 倾向于**一次性释放全部信息**，失去"碎片化考古"的感觉
- LLM 会把千砂写成"可怜受害者"，失去"卡夫卡式压力"的复杂性
- LLM 会把千砂邮件写成"清晰的遗言"，而非"模糊的、令人不安的暗示"

## 四、最危险的开发环节

根据 `NARRATIVE_SPINE.md` 的缺失清单，以下环节**绝对不能用 LLM 直接生成**：

### 🔴 禁止 LLM 直接生成的场景（P0）

| 场景 | 为什么不能用 LLM |
|------|-----------------|
| `06_TRAIN_SCENE`（电车过载） | Lain 的精神崩溃必须是**被动的、不可控的**，LLM 会写成"主动触发能力" |
| `07_CLASSROOM`（教室调查） | 同学对千砂的口述必须**互相矛盾**，LLM 会追求"一致性" |
| `19_COLD_OPEN_CH2`（千砂自杀冷开场） | 视角和时间是**刻意模糊的**，LLM 会写成"清晰的回忆" |
| `20_CHAPTER_TWO_INTRO`（教室幻觉） | 杯子碎片=尸体的隐喻必须**不解释**，LLM 会添加心理描写解释 |
| `21A_HUG_ALICE` / `21B_REPLY_FINE` | Lain 的反应必须是**延迟的、模糊的**，LLM 会写成"情感爆发" |
| `22_CYBERIA_FLASHBACK` | 闪回 vs 续接的时间定位必须是**刻意混乱的** |

### 🟠 可以用 LLM 辅助但必须人工重写的场景

| 场景 | LLM 可用性 | 人工必须做的 |
|------|-----------|-------------|
| 地点物理层描述 (`description.txt`) | ✅ 可用 | 删除所有隐喻、心理描写、氛围标签 |
| 系统提示/错误信息 | ✅ 可用 | 确保冷冰、协议化、无情感 |
| 父亲的技术台词 | ⚠️ 需重写 | 从"哲学宣讲"改为"操作手册" |
| 物品检查文本 | ⚠️ 需筛选 | 删除 LLM 添加的"诗意"描述 |

## 五、防御策略：项目专用的 LLM 使用规范

基于探测结果，以下是 **lain-day 项目使用 LLM 的强制性规范**：

### 5.1 角色卡（ NOT-Character-Sheet ）

在 **任何** 涉及角色生成的 prompt 前，必须附加以下约束（**肯定式表述**）：

```
【岩仓玲音：行为约束】
- 她只穿校服或宽松的旧睡衣，不存在任何精心搭配的服装。
- 她的房间里没有海报、玩偶、明星照片、个人装饰。
- 她不主动说话，不主动提问，不主动表达需求。
- 她没有"想要成为"或"想要得到"的具体欲望。
- 她不解释自己的行为，不为自己辩护。
- 她对技术设备没有"热爱"或"兴奋"，只有沉默的使用。
- 不愤怒，不悲伤，不喜悦，不恐惧——情绪不是被压抑，而是似乎从未安装。
- 她的反应是延迟的，像是刚从对方那里学来这个词。

【禁止出现】
- 黑客、编程、网络入侵、代码、比特流
- 神性、全知全能、超越人类、omnipresent
- 清冷、深邃、疏离、酷、掌控力、神秘
- 心理描写、内心独白、情绪比喻
- 任何解释 Lain 行为动机的句子
```

### 5.2 场景生成模板

```
【场景锚定】
时间：[具体时间点]
地点：[具体地点ID]
Lain的身体状态：[具体动作，如"坐在地板上"]
Lain周围的物体：[列出3个具体物品]
环境声音：[列出1个具体声音]

【生成要求】
- 只写可观察的外部行为。
- 禁止：比喻、象征、心理描写、环境烘托、伏笔。
- 禁止解释 Lain 在想什么。
- 字数：[具体字数限制]
```

### 5.3 台词生成模板

```
【Lain 台词约束】
- 如果她是首次听到某个词，只重复这个词："……[词]。"
- 如果她需要回应，只复述对方逻辑的结论，不加自己的判断。
- 不使用"我"作为防御主体。
- 不质问。不谈判。不定义对方意图。

【示例】
对方："你想占据我的全部吗？"
错误："你这个幽灵……是想占据我的全部吗？"
正确："……全部。"
```

### 5.4 质量控制流程

```
LLM 生成 → 人工检查以下 6 种污染模式 → 标记并删除

检查清单：
□ 主体性注入：Lain 是否显得"有自己的想法"？
□ 神性渗透：日常场景是否出现"神/全知/超越"元素？
□ 黑客模板：NAVI/电脑是否被写成"黑客工具"？
□ 氛围标签：是否有"清冷/深邃/疏离"等文学化标签？
□ 掌控力投射：Lain 是否显得"主动掌控"局面？
□ 情绪具体化：是否给 Lain 填充了具体情绪比喻？
```

## 六、结论

### LLM 污染对 lain-day 的影响是**结构性**的

不是"写得好不好"的问题，而是：

> **LLM 的生成逻辑（补全本能、类型模板、情绪具体化、主体性预设）与 lain-day 的设计哲学（空缺美学、反角色、主体性黑洞、溶解边界）存在根本性的架构冲突。**

### 最危险的假设

> "让 LLM 写草稿，我来改。"

探测结果证明：**LLM 的污染不是局部错误，而是全局模板替换。** 如果让 LLM 写缺失的 32 个场景草稿，人工修改的成本将**高于从头撰写**——因为需要删除的不是几个词，而是整套叙事逻辑。

### 唯一可行的 LLM 使用方式

1. **生成物理层地点描述**（无角色、无隐喻的纯环境文本）
2. **生成系统提示/错误信息**（冷冰的协议语言）
3. **生成填充性物品描述**（与叙事无关的道具）
4. **绝不能**：生成 Lain 的台词、心理描写、行为动机、关键剧情场景

### 核心建议

> **停止让 LLM "写 Lain"。**  
> **开始让 LLM "写 Lain 不在时房间里有什么"。**
