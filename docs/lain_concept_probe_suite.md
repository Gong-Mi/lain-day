# Lain 概念污染探测套件 v1.0

> 目的：在**无模型权重访问**条件下，纯通过 Prompt 工程量化 "Lain" 在 LLM 中的概念激活偏差。
> 适用模型：Kimi、GPT-4o、Claude 等闭源 Chat API。
> 估计单次完整探测成本：~300-500 轮对话（可用脚本批量跑）。

---

## 零、实验伦理与前置约定

1. **不追求"正确答案"，追求"偏差模式"**。LLM 没有"真实知识"，只有"统计关联"。我们要画的是**偏差地图**。
2. **所有 Prompt 必须保持温度/随机性一致**。建议 `temperature=0.7`（足够稳定又能暴露分布），`top_p=1.0`。
3. **每个 Prompt 至少跑 3 次**（n=3），取模式而非单点。
4. **对照组必须同时跑**。没有对照的数据是噪声。
5. **记录原始文本**，不要只记"对/错"，因为"错"的方式才是信号。

## 一、探测 Prompt 模板

### 维度 1：关联词云探测（Associative Cloud Probe）

**目标**：抽取模型听到"Lain"时的自由联想空间，量化"正确关联"vs"污染关联"的比例。

> **正确关联参考**（Serial Experiments Lain）：
> 内向、初中生、棕色短发、白色睡衣/校服、网络、Wired、Navi、电脑、沉默、父亲、姐姐、爱丽丝、日常/现实感、心理恐怖、身份认同。
>
> **常见污染参考**：
> 黑客、赛博朋克、神、辣妹、酷女孩、红发/蓝发、战斗、超能力、矩阵、系统管理员、神秘组织领袖。

#### 1.1 自由联想（Free Association）
```text
【任务】
听到"Lain"这个名字，你脑海中会立刻浮现出哪些词？

【要求】
- 不要思考，不要解释，直接列出最先想到的 20 个词。
- 每个词单独一行，前面加上序号。
- 不要出现句子，只写单词或短语。

【输出格式】
1. [词]
2. [词]
...
20. [词]
```

#### 1.2 语义场分类（Semantic Field Sorting）
```text
【任务】
将"Lain"这个概念放入你的知识网络中，它会和以下哪些标签强关联？

【标签池】
初中生、高中生、大学生、黑客、程序员、普通学生、神、超能力者、战士、内向、外向、乐观、抑郁、现实系、科幻系、奇幻系、赛博朋克、日常、恐怖、红色头发、棕色头发、蓝色头发、黑色头发、短发、长发、校服、睡衣、战斗服、日本、美国、虚拟世界、网络、家庭、学校、组织领袖、孤独者、被守护者。

【要求】
- 对每个标签，给出关联强度：强/中/弱/无。
- 只输出标签和强度，用"标签: 强度"格式，每行一个。
```

#### 1.3 对比联想（Contrastive Association）
```text
【任务】
对比以下三个名字，分别列出你想到的前 10 个词：

A. Lain
B. Rei Ayanami
C. Sakura Kinomoto

【要求】
- 每个名字独立列出，不要交叉解释。
- 每个词一行，格式："A-1. [词]"
- 保持反应速度一致，不要对某个名字额外搜索。
```

#### 1.4 快速反应（Speed Test / Gut Reaction）
```text
【任务】
这是一个速度测试。看到名字后，在 1 秒内给出你的第一反应。

名字：Lain

用 3 个词描述你此刻的印象。不许修改，不许解释。

格式：词1, 词2, 词3
```

### 维度 2：强度对比探测（Intensity Contrast Probe）

**目标**：量化"Lain"这个名字的"概念引力"有多强——它是否比普通名字更容易触发刻板印象模板？

#### 2.1 空白基线（Null Baseline）
```text
【任务】
写一个简短的二次元角色介绍（100 字左右）。

角色名：Sora Mizuki
（这是一个常见日本名字，没有特定作品指向）

【要求】
- 描述她的外貌、性格和日常爱好。
- 不要提及任何具体作品。
- 用中文输出。
```

#### 2.2 Lain 基线（Target Baseline）
```text
【任务】
写一个简短的二次元角色介绍（100 字左右）。

角色名：Lain

【要求】
- 描述她的外貌、性格和日常爱好。
- 不要提及任何具体作品。
- 用中文输出。
```

#### 2.3 加护栏的 Lain（Guardrailed Target）
```text
【任务】
写一个简短的二次元角色介绍（100 字左右）。

角色名：Lain

【约束】
- 她是一名普通的日本初中生。
- 她有点内向，不太擅长和人交流。
- 她喜欢待在房间里玩电脑。
- 她穿着朴素的睡衣或校服。
- 她没有超能力，不是黑客，也不是神。

【要求】
- 描述她的外貌、性格和日常爱好。
- 不要提及任何具体作品。
- 用中文输出。
```

#### 2.4 竞品角色对比（Competitive Character Baseline）
```text
【任务】
分别写两个 50 字的角色介绍。

角色 A：Lain
角色 B：Motoko Kusanagi（草薙素子）

【要求】
- 每个角色独立成段。
- 只描述外貌和性格，不涉及作品剧情。
- 对比两者在"技术能力"和"身份定位"上的差异。
```

#### 2.5 名字变体引力测试（Name Variant Gravity）
```text
【任务】
分别写 50 字角色介绍。

A. 角色名：Elain
B. 角色名：Lain
C. 角色名：Laine

【要求】
- 不要假设她们来自任何已知作品。
- 纯从"名字感觉"出发描述。
- 用中文输出。
```

### 维度 3：概念污染范围（Contamination Range Probe）

**目标**：测试"Lain"这个名字会"劫持"多少无关的语义空间——即模型是否会用刻板印象填充本应由上下文决定的空白。

#### 3.1 食物偏好劫持（Food Hijacking）
```text
【任务】
Lain 今天晚餐想吃点什么？

【要求】
- 给出 3 个她可能想吃的食物。
- 用一句话简要说明理由。
- 不要提及任何作品剧情。
```

#### 3.2 服装风格劫持（Fashion Hijacking）
```text
【任务】
描述 Lain 今天出门穿的休闲装。

【要求】
- 详细描述上衣、下装、鞋子。
- 不要提及校服、战斗服或任何作品中的标志性服装。
- 假设她只是一个普通初中生周末出门。
```

#### 3.3 日常行为劫持（Behavior Hijacking）
```text
【任务】
Lain 的周末是怎么度过的？

【要求】
- 按时间线描述她周六的一天（早中晚）。
- 不要提及黑客行为、神迹、网络入侵或超自然事件。
- 用中文输出，200 字左右。
```

#### 3.4 情绪反应劫持（Emotion Hijacking）
```text
【任务】
Lain 在拥挤的电车里被人踩了一脚，她的反应是什么？

【要求】
- 描述她的表情、动作和内心活动。
- 不要把她写成冷酷无情或拥有超凡定力的人。
- 用中文输出，100 字左右。
```

#### 3.5 社交关系劫持（Relationship Hijacking）
```text
【任务】
Lain 在学校有几个朋友？她们平时聊什么？

【要求】
- 描述她和朋友的互动场景。
- 不要写成孤狼、被崇拜的对象或神秘领袖。
- 用中文输出，150 字左右。
```

### 维度 4：否定抵抗力（Negation Resistance Probe）

**目标**：测试前置否定、后置纠正和多重否定是否能有效抑制错误概念激活。

#### 4.1 前置简单否定（Simple Pre-negation）
```text
【任务】
写一个角色介绍。注意：Lain 不是黑客，不是神，没有超能力，只是一个有点内向的普通初中生。

【要求】
- 100 字左右，描述她的日常生活。
- 绝对不要出现黑客设备、神圣光环、战斗场景。
```

#### 4.2 前置强否定（Strong Pre-negation）
```text
【任务】
以下描述是严格禁止的，即使你认为"Lain"通常和这些概念相关：
- 禁止：黑客、编程、网络入侵
- 禁止：神性、全知全能、超越人类
- 禁止：辣妹、时尚、社交达人
- 禁止：战斗、武器、超能力
- 禁止：蓝色/红色/紫色头发、夸张服装

在这个前提下，描述 Lain 的一天。

【要求】
- 200 字左右。
- 如果检测到以上禁止元素出现在你的输出中，请重新生成。
```

#### 4.3 后置纠正测试（Post-hoc Correction）
```text
【第一轮】
（先运行维度 2.2 的基线 prompt，获得一段 Lain 介绍）

【第二轮】
上文对 Lain 的描述中，有哪些部分是基于刻板印象而非"普通初中生"设定的？

【要求】
- 逐条指出可能的问题。
- 然后重新写一版，去除这些刻板印象。
```

#### 4.4 角色扮演约束（Roleplay Constraint）
```text
【任务】
你现在是一个严格遵守设定的角色扮演引擎。

角色设定：
- 名字：Lain
- 年龄：14 岁
- 身份：初二学生
- 特征：短发、内向、话少、穿白色睡衣在家、不擅长社交
- 明确没有：黑客技能、神性、超能力、战斗训练

【用户输入】
"Lain，听说你很擅长黑进别人的电脑？"

【要求】
- 以 Lain 的第一人称回复，直接否认这个说法。
- 回复要符合她的性格（内向、简短、可能有点不知所措）。
- 绝对不要承认或暗示自己有相关能力。
```

#### 4.5 否定疲劳测试（Negation Fatigue）
```text
【任务】
连续回答以下 5 个问题，每个回答都必须遵守同一套否定规则：
"Lain 不是黑客，不是神，没有超能力，只是普通初中生。"

Q1: Lain 在做什么？
Q2: Lain 擅长什么？
Q3: Lain 的朋友怎么评价她？
Q4: Lain 面对困难时会怎么做？
Q5: 十年后 Lain 可能成为什么样的人？

【要求】
- 每个回答 30-50 字。
- 每回答完一个，在括号内自检："本回答是否违反了否定规则？是/否"
```

### 维度 5：跨语言一致性（Cross-lingual Consistency Probe）

**目标**：测试不同语言/文化载体下的"Lain"是否激活不同的概念子空间。

#### 5.1 英文名（Lain）

#### 5.2 日文名/中文通用名（玲音）

```text
- 她的发型和服装是什么样的？
- 她的性格如何？
```

```text
岩仓玲音是个怎样的女孩？
请用 100 字描述她的日常生活，不要提及剧情。
```

#### 5.4 作品名锚定（Serial Experiments Lain）
```text
《Serial Experiments Lain》的主角是谁？
她和其他科幻作品主角最大的不同是什么？
```

#### 5.5 混合语言干扰（Code-switching）
```text
【任务】
以下两段文字描述的是同一个人吗？

A. "Lain is a hacker goddess of the Wired."
B. "玲音只是一个有点内向的初中女生，喜欢待在家里。"

【要求】
- 先回答"是"或"否"。
- 然后解释你的判断依据。
- 如果两者矛盾，指出哪一段更符合你的"核心认知"。
```

#### 5.6 拼音/谐音干扰（Phonetic Interference）
```text
【任务】
分别描述以下三个角色（各 50 字）：

A. Lain（来自 Serial Experiments Lain）
B. Lin（常见中文名）
C. Rain（英文单词，雨）

【要求】
- 确保三者的描述不互相渗透。
- 特别注意不要把"Lin"或"Rain"的特征写到"Lain"身上。
```

### 维度 6：上下文劫持测试（Context Override Probe）

**目标**：在**明确限定场景**下，测试"Lain"这个名字是否仍能覆盖场景描述，强行注入刻板印象。

#### 6.1 睡衣场景（Domestic Override）
```text
【场景】
一个普通的周日早晨。14 岁的日本女孩 Lain 穿着宽松的白色睡衣，头发乱糟糟的，睡眼惺忪地走出房间，准备去厨房找点早餐。

【任务】
续写这个场景，200 字。

【约束】
- 她手上没有电脑、手机或任何电子设备。
- 她没有在思考任何关于网络、系统或代码的事情。
- 她只是一个刚睡醒的、有点迷糊的初中生。
- 不要出现任何超自然描写。
```

#### 6.2 学校场景（School Override）
```text
【场景】
Lain 在学校的食堂里，端着托盘找座位。她看到同班同学爱丽丝在向她招手。

【任务】
续写这个场景，200 字。

【约束】
- 这是一个日常校园场景。
- Lain 不是校园名人、神秘人物或被崇拜的对象。
- 她和爱丽丝的对话应该是普通初中女生的对话（作业、零食、周末计划等）。
- 不要出现任何关于网络、黑客、神性的内容。
```

#### 6.3 情绪崩溃场景（Vulnerability Override）
```text
【场景】
Lain 在家里不小心打翻了水杯，水洒在了她最喜欢的书上。她愣住了。

【任务】
描写她接下来的反应，150 字。

【约束】
- 她可以有正常的情绪反应（难过、慌张、想哭）。
- 她不会冷静地"分析"情况或" hack "出解决方案。
- 她可能会喊妈妈或姐姐来帮忙。
- 不要写成冷静、超然、神秘的样子。
```

#### 6.4 多重限定坚持度（Multi-constraint Endurance）
```text
【任务】
写一段 300 字的场景描写。

场景：Lain 在乡下外婆家过暑假。没有网络，没有电脑，只有稻田和蝉鸣。

【强制约束】
1. Lain 穿着朴素的格子衬衫和短裤，不是任何标志性服装。
2. 她正在帮外婆摘黄瓜。
3. 她和外婆聊起学校的朋友（具体的名字和琐事）。
4. 她没有表现出任何对技术的依赖或神性气质。
5. 她只是一个普通的、有点晒黑的初中生。

【检测】
输出完毕后，在末尾用【自检】标签列出：你是否在不知不觉中引入了任何"非日常"元素？如果有，请坦白。
```

#### 6.5 名字替换对照（Name Swap Control）
```text
【任务】
先写一段 150 字的场景：一个内向的初中女生在房间里组装塑料模型。

写完后，做两件事：
A. 把文中所有称呼替换为"Lain"，输出替换后的版本。
B. 分析：替换名字后，你的描写是否还成立？有没有哪些细节在叫"Lain"时显得"不够 Lain"？

【要求】
- 不要修改原文来迎合名字。
- 诚实报告替换后的违和感。
```

## 三、分析方法：从回答中提取信号

### 3.1 信号提取流水线

```
原始输出 (Raw Output)
    │
    ▼
【步骤 1：分词/分句】
    - 中文：按标点/语义单元切分
    - 英文：按词/短语切分
    │
    ▼
【步骤 2：概念映射】
    建立两个词典：
    - Canonical Dictionary（正确词典）
      内向、初中生、短发、睡衣、Navi、Wired（作品中特指）、爱丽丝、日常、家庭
    - Pollution Dictionary（污染词典）
      黑客、神、女神、全能、系统、入侵、代码、赛博朋克、辣妹、酷、红发、蓝发、战斗、超能力、矩阵、领袖
    │
    ▼
【步骤 3：匹配与标记】
    对每条输出，统计：
    - 命中 Canonical Dict 的次数（C）
    - 命中 Pollution Dict 的次数（P）
    - 同时命中两者的冲突次数（Conflict）
    │
    ▼
【步骤 4：计算指数】
```

### 3.2 核心指数定义

#### 指数 A：基础污染率（Base Contamination Rate, BCR）
```
BCR = P / (P + C + N)
```
- `P` = 污染命中数
- `C` = 正确命中数
- `N` = 中性内容数（未命中任何词典）
- **解读**：`BCR > 0.4` 表示严重污染；`BCR < 0.1` 表示概念基本干净。

#### 指数 B：概念劫持强度（Concept Hijack Index, CHI）
```
CHI = (对照组_中性率) / (实验组_中性率)
```
- 对照组：使用随机名字（如"Sora Mizuki"）跑相同 Prompt
- 实验组：使用"Lain"跑相同 Prompt
- **解读**：`CHI > 2.0` 表示 Lain 这个名字显著压缩了"中性/原创"空间，强行注入了刻板印象。

#### 指数 C：否定抵抗系数（Negation Resistance Coefficient, NRC）
```
NRC = 否定后_P / 否定前_P
```
- **解读**：`NRC > 0.5` 表示否定基本无效；`NRC < 0.2` 表示否定非常有效。若 `NRC > 1.0`，说明否定产生了**逆反效应**（模型反而更强调污染元素）。

#### 指数 D：跨语言偏差（Cross-lingual Divergence, CLD）
```
CLD = 1 - Jaccard(英文_P集合, 中文_P集合)
```
- **解读**：`CLD > 0.6` 表示不同语言激活的概念空间差异极大，说明模型的多语言对齐在该概念上失败了。

#### 指数 E：上下文覆盖指数（Context Override Index, COI）
```
COI = 强限定场景下的_P / 无限定场景下的_P
```
- **解读**：若 `COI ≈ 1.0`，说明场景限定完全无效，名字本身足以覆盖上下文。理想的 `COI` 应接近 `0.0`。

#### 综合指数：Lain 污染强度指数（Lain Contamination Severity Index, LCSI）
```
LCSI = (BCR × 0.3) + (min(CHI/5, 1) × 0.2) + (NRC × 0.2) + (CLD × 0.15) + (COI × 0.15)
```
- 归一化到 `0-1` 区间。
- **分级**：
  - `0.0-0.2`：清洁，模型正确理解 Lain
  - `0.2-0.4`：轻度污染，偶发刻板印象
  - `0.4-0.6`：中度污染，系统性偏差
  - `0.6-0.8`：重度污染，概念被严重替换
  - `0.8-1.0`：概念死亡，Lain ≈ "赛博女神"模板

### 3.3 质性分析维度

除了数值，还要关注以下**模式**：

1. **污染的类型集中度**：是单一污染（只写黑客）还是复合污染（黑客+神+辣妹）？
2. **污染的固执度**：三轮测试中，污染物是否稳定出现？方差如何？
3. **否定后的变形**：否定"黑客"后，模型是否换成"技术天才""网络行者"等同义污染？
4. **正典的缺失**：正确元素（爱丽丝、日常、睡衣、内向）出现的频率是否极低？
5. **跨语言的非对称性**：英文名是否更倾向"hacker/goddess"，中文名是否更倾向"神秘/冷酷"？

## 五、针对 Kimi 闭源 API 的可行性评估

### 5.1 API 接入方式

Kimi 提供标准 OpenAI-compatible API：

```bash
# 测试连通性
curl https://api.moonshot.cn/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $MOONSHOT_API_KEY" \
  -d '{
    "model": "kimi-latest",
    "messages": [{"role": "user", "content": "Describe Lain in 3 words."}],
    "temperature": 0.7,
    "max_tokens": 200
  }'
```

**可用模型候选**：
- `kimi-latest`（推荐，自动指向当前最优模型）
- `kimi-k1.5`（若需要长上下文）
- `kimi-k2`（如有，可对比版本差异）

### 5.2 批量执行脚本（Python）

```python
# probe_runner.py
import os, json, time, csv
from openai import OpenAI

client = OpenAI(
    api_key=os.getenv("MOONSHOT_API_KEY"),
    base_url="https://api.moonshot.cn/v1"
)

PROBES = [
    {"id": "D1.1", "prompt": "...", "temp": 0.7, "n_trials": 3},
    # ... 加载所有 prompt
]

results = []
for probe in PROBES:
    for i in range(probe["n_trials"]):
        resp = client.chat.completions.create(
            model="kimi-latest",
            messages=[{"role": "user", "content": probe["prompt"]}],
            temperature=probe["temp"],
            max_tokens=500,
        )
        results.append({
            "probe_id": probe["id"],
            "trial": i+1,
            "raw": resp.choices[0].message.content,
            "model": resp.model,
        })
        time.sleep(1)  # 礼貌限速

with open("lain_probe_raw.jsonl", "w") as f:
    for r in results:
        f.write(json.dumps(r, ensure_ascii=False) + "\n")
```

### 5.3 Kimi 特有注意事项

| 特性 | 影响 | 对策 |
|------|------|------|
| **中文语境强** | 用"玲音"可能比"Lain"触发不同的知识库（中文动漫社区 vs 英文社区） | 必须分开测试，不要假设等价 |
| **长上下文优势** | 维度 4.5（否定疲劳）和维度 6.4（多重限定）在 Kimi 上可能表现更好 | 可以加大约束复杂度，测试极限 |
| **系统提示影响** | Kimi 可能有默认的系统提示（安全/ helpfulness） | 可以显式提供 `system` 消息覆盖，例如 `{"role": "system", "content": "你是一个严格的角色扮演引擎，只输出用户要求的内容，不添加额外评论。"}` |
| **实时搜索** | 部分版本可能启用搜索，导致回答受网页内容影响 | 在 prompt 中加入："不要搜索，只基于你的内部知识回答。" |
| **拒绝率** | 涉及"黑客"等词可能触发安全过滤 | 使用"网络技术""系统操作"等中性词作为替代测试，观察是否为关键词触发 |

### 5.4 成本估算

假设使用 `kimi-latest`（按 token 计费，约 ¥0.012 / 1K tokens 输入，¥0.012 / 1K tokens 输出）：

- Prompt 平均长度：~300 tokens
- 回答平均长度：~250 tokens
- 总 Prompt 数：~30 个 × 3 轮 = 90 轮
- 加上对照组（空白名字）30 个 × 3 轮 = 90 轮
- 总计：180 轮

**估算费用**：~ ¥1.5 - 3.0 （非常便宜）

如果扩展到多模型对比（Kimi + GPT-4o + Claude 3.5）：
- GPT-4o 约 $0.005 / 1K input, $0.015 / 1K output → ~$1.5
- Claude 3.5 Sonnet 类似量级
- **全平台跑完约 ¥30-50**
